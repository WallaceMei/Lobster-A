## Step B. 填配置（龙虾雷达项目）

### B.1 复制 .env 模板

```powershell
cd C:\quant_project\龙虾雷达
copy .env.template .env
notepad .env
```

填入以下 key（去掉等号后的空白）：
- `LLM_PRIMARY_API_KEY=sk-xxx` (你的 DeepSeek key)
- `LLM_SECONDARY_API_KEY=AIza-xxx` (你的 Gemini key, https://aistudio.google.com 免费拿)
- `MINIMAX_API_KEYS=xxx` (你的 MiniMax key)

> 注: 不再需要 `FEISHU_WEBHOOK` (架构已改为 Qclaw 原生推送, 见 B.2)

### B.2 Qclaw 远控通道配置

**架构说明 (2026-04-24 更新)**:
龙虾雷达**不再使用飞书自定义群机器人 Webhook**, 改为 **Qclaw 原生通道**:
- 4 个 Qclaw 任务 (T1-T4) 的执行结果以 Markdown 格式输出
- Qclaw 平台已接入飞书通道, **自动**把任务输出转发到 Wallace 飞书
- 提示词内不再 POST 任何 URL, 输出即推送

**Wallace 需做**:
1. 在 Qclaw 客户端确认飞书通道已接入 (你已完成: "飞书消息"对话框能正常通信)
2. 确认 Qclaw 客户端在工作时间常开 (任务调度依赖)
3. **不需要**创建任何飞书自定义机器人或 Webhook

**未配的通道** (按 Wallace 决策, 暂不需要):
- ❌ 微信通道 (Wallace 暂不需要)
- 🔇 自定义 Webhook (DSA `.env` 中已注释)

**应急回退路径** (如果 Qclaw 通道出问题):
- 飞书 App ID/Secret 已存在 DSA `.env` (FEISHU_APP_ID / FEISHU_APP_SECRET)
- 必要时可启用 DSA 自带的 lark-oapi 推送作为备用

## Step C. 跑验证脚本

- 系统托盘 → Clash 图标右键 → 退出（或暂停）
- 跑完测试再开

### C.1 初始化数据库（仅首次跑）

```powershell
cd C:\quant_project\龙虾雷达
python scripts\init_dedupe_db.py
```

预期：`[OK] 数据库初始化完成` + `已创建表: ['daily_push_count', 'pushed_news', 't4_candidates']`

### C.2 验证 Qclaw 推送通道

[废弃] 原 `scripts\verify_feishu.py` 已归档为 `.deprecated` (架构变更, 不再走 Webhook)。

**新验证方式**:
1. 在 Qclaw 客户端打开"飞书消息"对话框
2. 输入任意一条测试消息 (如 "ping")
3. 看飞书 App 是否收到回复

如果通道正常 → 4 个 Qclaw 任务的输出会自动经此通道送达飞书

### C.3 数据源连通性测试

```powershell
python scripts\test_all_data_sources.py
```

预期：7 个数据源全 ✅，最后打印 `[OK] 关键数据源全通, 可以进入 M2`

❌ 失败排查（按数据源）：
- AkShare 失败 → Clash 没退干净，再检查一遍系统托盘
- DSA API 失败 → Step A 没启动 webui.py
- DeepSeek 失败 → key 错或没钱
- Gemini 失败 → key 错 / 国内可能要代理（这条独立处理，可暂时跳过）
- MiniMax 失败 → key 错或欠费

## Step D. 在 Qclaw 配置 4 个任务

### D.1 准备工作

打开 Qclaw 客户端，进入"任务"模块。

每个任务的"提示词"内容 = `prompts/Tx_xxx.md` 文件的**完整内容**复制粘贴。

### D.2 创建任务 T1：竞价情报

| 字段 | 填什么 |
|---|---|
| 任务名 | 龙虾雷达-T1-竞价情报 |
| 描述 | 9:24 集合竞价情报扫描 |
| 触发方式 | 定时触发 |
| Cron 表达式 | `0 24 9 ? * MON-FRI` (每个工作日 9:24:00) |
| 提示词 | 复制 `C:\quant_project\龙虾雷达\prompts\T1_竞价情报.md` 全文 |
| 关联 SKILL | 把 `skills/xiaolongxia_v4.md` 全文也粘入提示词末尾，或在 Qclaw 里设置 SKILL 引用（视 Qclaw 实际功能） |
| LLM 模型 | DeepSeek (deepseek-chat) |
| 超时 | 5 分钟 |
| 失败重试 | 1 次 |

### D.3 创建任务 T2：早盘密集

| 字段 | 填什么 |
|---|---|
| 任务名 | 龙虾雷达-T2-早盘密集 |

| 提示词 | `prompts/T2_早盘密集.md` 全文 |
| 静音段 | 在提示词内逻辑已处理 (11:25-11:30) |

### D.4 创建任务 T3：盘中常规

| 字段 | 填什么 |
|---|---|
| 任务名 | 龙虾雷达-T3-盘中常规 |
| Cron | `0 30,40,50 10 ? * MON-FRI` + `0 0,10,20,30,40,50 11 ? * MON-FRI` + 13:00-15:00 每 10 分钟（具体 cron 看 Qclaw 文档怎么写连续区间） |
| 提示词 | `prompts/T3_盘中常规.md` 全文 |
| 静音段 | 提示词内已处理 (11:30-13:00 + 14:55-15:00) |

### D.5 创建任务 T4：收盘潜力

| 字段 | 填什么 |
|---|---|
| 任务名 | 龙虾雷达-T4-收盘潜力 |

## 跨日运行注意

### 每天首次启动

每天早上 8:50 之前打开两件事：
1. **DSA 后端**: `python webui.py` (常驻, 关了就没了)
2. **Qclaw 客户端**: 也要保持开启 (任务调度依赖它)

### 节假日

A 股休市日（周末/法定节假日）任务不该执行。已在每个提示词的 cron 里限定 `MON-FRI`，但**法定节假日的周一至周五**仍会触发。

简单方案：节假日早上手动在 Qclaw 暂停 4 个任务，节后再启用。

### 系统重启后

如果电脑重启：
1. 重启后第一件事重新启动 DSA: `python webui.py`
2. Qclaw 客户端会自动恢复任务
